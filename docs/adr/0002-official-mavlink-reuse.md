# ADR 0002：复用官方 MAVLink

## 状态

已接受

## 背景

项目需要稳定支持 ArduPilot 和 PX4 的 MAVLink 通信。自行从零实现 MAVLink 会提高协议风险、维护成本和兼容性问题。

## 决策

项目必须尽可能复用官方 MAVLink 定义和官方代码生成产物。

在生成产物外部保留一层薄适配器，把原始协议细节隔离在后端内部，避免业务代码直接依赖生成代码细节。

## 备选方案

### 自研 MAVLink 实现

优点：

- 完全可控。

缺点：

- 风险高。
- 重复造轮子。
- 与 ArduPilot/PX4 生态兼容性更差。

### 部分混合复用

优点：

- 初始依赖面较小。

缺点：

- 协议处理不一致。
- 长期维护负担更高。

## 影响

1. 官方 MAVLink 仓库是协议事实来源。
2. 生成产物必须隔离在专门目录。
3. 应用代码必须消费适配器抽象，而不是直接依赖生成产物内部细节。
4. 任何偏离官方定义的行为都必须通过 ADR 记录并评审。
