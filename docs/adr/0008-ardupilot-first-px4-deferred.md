# ADR-0008：ArduPilot 优先，PX4 支持延后

状态：已接受  
日期：2026-10-12

## 背景

M-GCS 项目初期目标是"对标 Mission Planner 与 QGroundControl，优先服务 ArduPilot，兼容 PX4"。在开发过程中，发现同时支持两个固件系统会导致：

1. **开发资源分散**：每个功能需要适配两套固件协议、参数体系、飞行模式
2. **测试成本倍增**：需要维护 ArduPilot 和 PX4 两套 SITL 环境和测试用例
3. **质量风险增加**：PX4 相关功能缺乏实际验证，存在多个已知缺陷（KD-53 等）
4. **文档维护负担**：需要同时维护两套固件的对比文档和兼容性说明

当前代码库中 PX4 相关功能的实际状态：

- **参数系统**：PX4 参数元数据已集成（ADR-0007），但校准回读等功能硬编码 ArduPilot 参数名（KD-53）
- **飞行模式**：插件系统支持 PX4，但前端展示和模式切换未经实测
- **校准流程**：陀螺/加速度/磁罗盘校准在 PX4 上存在已知问题
- **任务协议**：基本兼容，但未系统验证 PX4 特有的任务命令

## 决定

**在 0.3.0 版本之前，聚焦 ArduPilot 固件支持，暂停 PX4 相关功能开发**。

具体措施：

### 1. 开发优先级

- ✅ **ArduPilot 功能**：全力开发和优化，确保生产可用
- ⏸️ **PX4 功能**：不主动开发新功能，不修复非阻塞性缺陷
- 🔒 **保留兼容层**：不删除 PX4 相关代码，保持架构扩展性

### 2. 测试与验证

- ✅ **ArduPilot SITL**：完整的端到端测试覆盖（Copter/Plane/VTOL/Rover）
- ⏸️ **PX4 SITL**：仅保持基础连接测试，不扩展新场景
- 📝 **已知问题**：PX4 相关缺陷在 `known-deviations.md` 登记为"延后修复"

### 3. 文档更新

- 更新 `README.md`：明确"当前版本聚焦 ArduPilot"
- 更新 `parity.md`：标注 PX4 功能为"计划支持"
- 删除或归档过时的 PX4 对齐文档

### 4. 用户沟通

- 应用启动时不显示 PX4 固件选项（保留在代码中）
- 文档中明确说明当前版本主要支持 ArduPilot
- 在 CHANGELOG 中说明此决策

## 后果

### 正面

- ✅ 开发资源集中在 ArduPilot，可以更快达到生产质量
- ✅ 测试覆盖更深入，质量更可控
- ✅ 文档更聚焦，用户学习曲线更平缓
- ✅ 减少维护负担，降低技术债务

### 负面

- ❌ PX4 用户无法使用当前版本
- ❌ 部分已实现的 PX4 功能暂时不可用
- ❌ 需要在未来版本补齐 PX4 支持

### 兼容性

- **代码层**：保留 PX4 插件、参数元数据、飞行模式映射
- **架构层**：固件插件系统仍然是可扩展的
- **未来迁移**：0.3.0 后可以快速恢复 PX4 支持

## 实施计划

### 立即执行（0.2.2 → 0.2.3）

1. **更新 README.md**：
   ```markdown
   无人机地面站，对标 Mission Planner 与 QGroundControl。
   
   **当前版本聚焦 ArduPilot 固件支持**。PX4 支持计划在 0.3.0+ 版本提供。
   ```

2. **更新 known-deviations.md**：
   - KD-53（PX4 陀螺校准）：状态改为"延后修复（PX4 功能延后）"

3. **归档文档**：
   - 移动 `docs/features/px4-parity.md` 到 `docs/archive/`
   - 保留 `docs/adr/0007-px4-parameter-metadata.md` 作为架构参考

4. **更新 CHANGELOG.md**：
   ```markdown
   ## [0.2.3] - 2026-10-12
   
   ### Changed
   - 开发策略调整：0.2.x 版本聚焦 ArduPilot 固件支持，PX4 支持延后至 0.3.0+
   ```

### 0.3.0 之前

- 不主动开发 PX4 功能
- 不修复 PX4 特有的非阻塞性缺陷
- 保持代码架构的可扩展性

### 0.3.0 及之后

届时重新评估：

- 用户对 PX4 支持的需求
- ArduPilot 功能的成熟度
- 团队资源和优先级

若决定恢复 PX4 支持：

1. 补齐测试覆盖（SITL 端到端场景）
2. 修复已知缺陷（KD-53 等）
3. 完整验证参数、校准、飞行模式
4. 更新文档和用户指南
