# UI

前端使用 Flutter，代码位于 `flutter_shell/`。目标是界面可替换、三端一致、组件统一。页面清单与控件映射见 `ui-pages.md`。

本文件分两类规则：约束（MUST）与建议（SHOULD）。每条约束写明违反后果和验证方式。

## 约束

**U1 可替换性**
页面只通过控制器访问业务，控制器只通过 backend 接口访问 FFI。
- 违反后果：更换视觉风格时需要改动业务逻辑。
- 验证：检查页面是否直接依赖 backend 实现或 `dart:ffi`（与 `architecture.md` 的 A5 相同）。

**U2 三端结构一致**
Windows、macOS、Android 的页面结构、组件和文字层级相同。平台差异只允许出现在窗口管理和原生集成层。
- 违反后果：同一功能在不同平台表现不同。
- 验证：CI 三端构建通过；合并前人工截图比对（见 U7）。

**U3 设计系统单点定义**
字号只取自 `MgTypography`，颜色只取自 `MgColors`，尺寸只取自 `MgMetrics`，字体族只在 `MgFonts` 中定义。业务页面中不得出现字面量数值或字体族名。界面统一使用 MiSans。
- `MgFonts` 内部的平台回退链（macOS `PingFang SC`、Windows `Microsoft YaHei UI`、Android `Noto Sans SC`）是允许的例外：它只用于 MiSans 缺失的生僻字与符号，属于 U2 允许的原生平台差异，且只出现在 `MgFonts` 内部。业务页面仍只能引用 `MgFonts`，不得自行指定回退。
- 违反后果：风格分裂，换主题的成本变高。
- 验证：`tools/check_ui_tokens.dart`（覆盖裸色值、裸字重、裸字号、硬编码字体族、裸圆角与行高）。开发者画廊 `lib/demo/component_gallery_demo.dart` 是唯一豁免文件：它并排对照 `macos_ui` 原始色板与字号，不属于业务页面。

**U4 只有标题加粗**
页面标题、区块标题、卡片标题、表头以外的文字一律使用 `w400`。
- 违反后果：层级混乱，页面之间的文字风格不一致。
- 验证：静态搜索 `FontWeight` 的使用，允许名单之外即为违规。

**U5 同类元素单一实现**
标题、表单行、按钮、状态标签、卡片、对话框、顶栏，每类只允许一种实现。页面内不得自造同类变体。
- 违反后果：页面像不同的软件，这是用户最关注的问题。
- 验证：评审时对照 `ui-pages.md` 的组件映射；截图比对。

**U6 规划先于开发**
新增页面或改动页面骨架前，必须先在 `ui-pages.md` 中登记布局、组件和 token 映射。
- 违反后果：页面各自为政，后续难以统一。
- 验证：评审时检查 `ui-pages.md` 是否已更新。

**U7 三端验收**
界面改动必须通过三端构建。合并前，由人工对同一页面的三端截图进行比对，差异须修复或登记。
- 违反后果：平台差异没有被发现。
- 验证：CI 构建结果与截图记录。

**U8 飞行命令入口确认**
飞行状态命令的界面入口必须经过确认组件，对应 `safety.md` 的 S3。
- 违反后果：误触导致飞机状态改变。
- 验证：UI 测试枚举入口。

## 建议

**复用组件 [SHOULD]**
新增控件前先查 `widgets/` 与 `components/`。已有组件能满足需求时，建议复用，而不是另写近似版本。

**少手绘 [SHOULD]**
优先使用 macOS 风格组件。普通控件建议不使用 `CustomPainter` 实现。

**文字与数字 [SHOULD]**
文字和控件建议垂直居中、使用固定行高。数字读数建议使用等宽数字（`tabularFigures`），避免数值变化时宽度跳动。
