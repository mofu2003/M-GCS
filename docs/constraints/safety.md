# 飞行安全

本文件分两类规则：

- **约束（MUST）**：违反即不得合并。每条写明违反后果和验证方式。
- **建议（SHOULD）**：默认采用。偏离时在设计说明或提交说明中写明理由。

与 QGC、MP 的对照见 `parity.md`。当前不符合规则的位置见 `known-deviations.md`。

## 约束

**S1 拒绝必须传播**
飞控拒绝命令（COMMAND_ACK 非 ACCEPTED，或 MISSION_ACK 报错）时，错误返回调用方，不得被吞掉，也不得转换成成功。
- 违反后果：操作者以为命令已生效，实际未执行。
- 验证：核心层测试模拟飞控拒绝，断言调用方收到错误。

**S2 命令结果以 ACK 为准**
布尔返回值只表示"已交给发送层"。判断成功必须匹配到对应的 ACK。界面不得把"已发送"显示为成功。
- 违反后果：界面显示成功，飞控实际未接受。
- 验证：测试断言未收到 ACK 时结果不为成功；界面测试覆盖"已发送"状态。

**S3 飞行状态命令必须确认**
范围：解锁、上锁、起飞、降落、返航、急停、模式切换、任务启动、Goto、Orbit、ROI，以及其他会立即改变飞机运动或状态的命令。界面入口必须经过确认组件（长按或对话框）。不得存在无确认的入口。
- 违反后果：误触导致飞机意外运动或状态改变。
- 验证：UI 测试枚举上述命令的入口，断言都经过确认组件；评审检查新增入口。

**S4 超时必须报错**
网络、串口、ACK 等待、任务传输、校准必须有超时。超时后返回明确错误，不得无限挂起。
- 违反后果：界面卡死，或操作者无法判断状态。
- 验证：测试注入无响应，断言超时后返回错误。

**S5 断链通知与状态失效**
链路断开时必须通知界面。依赖该链路的状态（解锁、当前模式）必须标记为"未知或过期"，不得显示为当前值。
- 违反后果：操作者依据过期的解锁状态操作。
- 验证：测试断开链路，断言通知发出，且状态字段被标记为过期。

**S6 固件专属值经插件获取**
模式号、参数名、命令编码、校准流程只能由固件插件提供。通用代码中不得出现这些值的字面量。
- 违反后果：更换或升级固件后行为错误。
- 验证：静态检查通用代码路径中是否出现已知模式号和参数名字面量。
- 参数名的落地方式：插件在 `core/src/config/ParameterDescriptors.json` 的 `roles` 段按机型 profile 提供「语义角色 → 固件参数名」，经 `mg_config_get_param_roles` 下发；前端只写语义角色（如 `pid.rate.roll.p`、`rc.map.yaw`），用 `ConnectionController.roleParam()` 解析。门禁 `tools/check_firmware_literals.py` 挡住新增字面量，`tools/firmware_literals_baseline.json` 保留为空表示已清零。

**S7 任务文件不静默覆盖**
`MissionDocument` 是唯一内部状态，上传飞控前从它编译 `MissionPlan`。不得改写用户原始文件，也不得在用户不知情时替换其内容。
- 违反后果：用户任务丢失或被替换。
- 验证：测试覆盖导入、导出、上传前后，原文件内容不变。

**S8 取消必须到达飞控**
可取消的长操作（校准、任务传输）取消时，必须向飞控发出对应命令。在飞控确认之前，界面不得显示为已停止。
- 违反后果：界面显示已取消，飞控仍在执行。
- 验证：测试断言取消触发对应命令；未确认前状态不为已停止。

## 建议

**写入类操作的确认 [SHOULD]**
任务上传、围栏与集结点上传、参数写入建议确认，因为它们会改变飞机后续的行为。QGC 与 MP 对这些操作都不确认，因此不做硬性要求。偏离时写明理由。安全相关的参数建议优先确认。

**确认方式与时长 [SHOULD]**
- 解锁与上锁：长按 500 ms，与 QGC 一致。
- 地图指令（Goto、Orbit、ROI、设置 Home、设置航向）：长按 3 s，参考 QGC。偏离时写明理由。

**超时与重试 [SHOULD]**
超时数值按操作类型设定，参考值见 `parity.md`。解锁命令不自动重试，其他命令可按有限次数重试，参考 QGC 的做法。

**ACK 匹配 [SHOULD]**
匹配 ACK 时同时校验目标系统与命令号，参考 MP 的做法。非 ACCEPTED 的结果应展示给用户，附命令名与结果，参考 QGC 的做法。

**断线后的恢复 [SHOULD]**
清零进行中的传输与校准并报错。断线后自动重连，采用退避策略。用户主动断开时不重连。参考 QGC 的做法。
