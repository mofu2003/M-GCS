# ADR 0003：使用本地 FFI 替代网络桥接

## 状态

已接受

## 背景

后端早期曾探索网络式桥接方案。对于同进程地面站架构，这条路线引入了不必要的复杂度：

- 增加本地网络依赖。
- 增加可避免的序列化开销。
- 扩大攻击面。
- 让平台行为更难预测。

本仓库需要一个本地、明确、可测试的集成边界。

## 决策

采用 **本地 C FFI 桥接层** 作为外部消费者与后端之间的集成边界。

后端编译为共享库，消费者直接调用导出的 C 函数。契约定义在 `bridge/ffi/ffi_api.h`，C++ 后端实现细节保持私有。

## 影响

1. FFI 边界只能使用 C 兼容类型。
2. 公共行为通过 FFI 契约进行版本化。
3. 返回 envelope 和错误映射成为稳定后端 API 的一部分。
4. 契约变化必须同步更新测试和文档。
5. bridge 层是一级架构边界，不是临时薄封装。
