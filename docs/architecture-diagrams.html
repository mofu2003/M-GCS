M-GCS 架构图

版本 v0.0.60 · 更新于 2026-10-01 · 结构说明以本文为准，精确行数和消费统计用 tools/audit_status.sh 复核

一、整体架构

四层单向依赖。前端只认 C ABI，后端不知道调用者是谁；箭头方向即依赖方向，不允许逆向。

飞控 / 仿真器 外部设备

ArduPilot（优先）或 PX4 飞控，通过 UART / UDP / TCP 发 MAVLink v2 帧；SITL 由后端 SitlLauncher 本地拉起。

▲▼MAVLink v2 字节流

① 表示层 · Flutter Shell flutter_shell/

Dart/Flutter，flutter_shell/lib 当前 29 个 .dart 文件。只做渲染与交互，不复制任何后端状态机。 ConnectionController 持有共享 Core 生命周期，任务、遥测、参数、校准和飞行命令由五个领域 backend 分别绑定动态符号。

macOS / Windows / Linux / AndroidFlutter 3.44.9 · Dart 3.12.2
▼dart:ffi · DynamicLibrary

② 契约层 · C FFI Bridge bridge/ffi/

唯一的对外稳定边界。ffi_api.h 是 umbrella，下挂 12 个领域头， 导出 288 个 mg_* 函数。只暴露 C 兼容类型，复杂结果走 JSON envelope。

43 .cc + 31 .h mg_create() → mg_destroy() mg_free_string() 释放 char*
▼C++ 直接调用（同进程，无 IPC）

③ 领域层 · C++17 Core core/

协议解析、连接生命周期、安全敏感命令、任务/参数传输、遥测缓存、校准、固件适配。 66 个实现文件 ≈ 19,015 行，72 个公开头文件。不得依赖任何 UI 框架。

transport · mavlink · vehicle · mission · calibration firmware · telemetry · config · geofence · ftp · log
▼

④ 平台抽象 + 第三方 core/src/platform/ · third_party/

platform_mutex / socket / filesystem 分 POSIX、Win32、Android 三套实现； 第三方仅 MAVLink C 生成头、cJSON、可选 FFmpeg。third_party/ 不修改。

三条硬契约

  • 依赖单向：flutter_shell → bridge/ffi → core → third_party。core/ 不得知道调用者是谁。
  • 内存所有权：FFI 返回的 char* 由调用方 mg_free_string() 释放；事件回调的 json 同理。
  • 契约成套：改 ffi_api*.h 必须同步声明 / 实现 / 测试 / API_CATALOG.md / 文档，缺一项即违规。

事件流（推）与查询流（拉）

  • 推：EventDispatcher::fire() → mg_event_callback_t → Dart 侧回调，30 种 mg_event_type_t。
  • 拉：Dart 调用 mg_*_get_* 取 JSON 快照，交给 notifyListeners() 驱动 AnimatedBuilder 重建。
  • 汇聚：mg_system_get_diagnostics() / mg_operations_get_snapshot() 让调用方不必自行拼接多个底层快照。

构建产物与门禁

  • mgcore.dylib / mgcore.dll / libmgcore.so
  • 后端：ctest 35/35（offline 21 + simulation 14）
  • 前端：flutter analyze 无告警；flutter test 21/20
分层泄漏（已修复）： 曾经 core/include/core/vehicle/vehicle.h 第 17 行是 #include "telemetry_cache.h"，而该文件实际位于 bridge/ffi/telemetry_cache.h，于是 core/vehicle 依赖了 bridge/ffi，方向被打破。 原因是根 CMakeLists.txt 把 bridge/ffi 挂到了 mgcore 的 PUBLIC include 路径上；此前"core 对 bridge/ffi 引用为 0" 的结论是用 bridge/ 前缀做文本匹配得出的，裸文件名 include 没被匹配到。 现已把 telemetry_cache.h 及其四个序列化器下沉到 core/include/core/telemetry/，bridge/ffi/ 只留同名转发头， 并在 test_bridge_architecture_guards.cc 增加 core→bridge 方向断言。
