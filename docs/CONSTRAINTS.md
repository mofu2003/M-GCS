# 开发约束

这些约束是长期维护边界。需要突破时，先写 ADR，再改实现。

## 语言和编码

1. 面向维护者、操作员和项目说明的文本默认使用中文。
2. 协议名、API 名、JSON 字段、文件名、目录名和行业通用缩写可以保留英文。
3. 自有文本目标状态是 UTF-8 + LF。
4. CRLF/BOM 归一化必须单独处理，不得混入功能改动。
5. 不为了中文化修改稳定 API、FFI 契约、JSON 字段或协议常量。

## 安全边界

1. 连接状态、命令发送、任务传输、参数写入、校准流程和遥测新鲜度都是安全敏感路径。
2. 持有后端共享状态锁时不得执行阻塞 I/O，也不得在持锁期间调用外部回调。
3. 操作员相关错误不能被吞掉；超时、拒绝、能力不可用必须明确暴露。
4. 未经明确确认，不得触发解锁、起飞、任务启动、电机测试、写参数、切模式或危险校准。
5. 真实飞控测试前必须确认飞控未解锁，并说明本次测试会触发哪些命令。
6. `hardware` 和 `manual` 测试不得进入默认自动化门禁。

## 后端约束

1. 优先复用官方 MAVLink 定义和生成产物。
2. 原始 MAVLink 细节必须封装在后端适配器之后。
3. ArduPilot/PX4 差异必须通过 firmware profile 和 capabilities 表达，调用方不得猜测固件行为。
4. 参数、任务、校准、命令和连接生命周期变化必须补回归测试。
5. 串口、TCP、UDP、断链处理、显式重连或遥测流请求变化至少运行聚焦测试和默认门禁。
6. 跨平台代码必须显式区分 Windows、Linux、macOS 和 Android。
7. Mission CAD 文档、几何、约束、编译、校验和持久化必须位于后端领域层，不得依赖任何前端语言、页面名称、地图 SDK 或 UI 控件字段。
8. `MissionPlan` 是面向飞控的派生模型，不能作为可编辑 Mission CAD 文档的唯一事实来源。
9. 后端不得依赖任何具体前端仓库、包管理器或 UI 框架。

## FFI 约束

1. C FFI 不暴露 C++ 类、模板、异常或所有权细节。
2. 所有返回给外部调用方的 `char*` 必须可由 `mg_free_string()` 释放。
3. `mg_event_callback_t` 的 `json` 参数也由回调方负责调用 `mg_free_string()`。
4. 新增 FFI 函数必须放入合适的 `ffi_api_*.h`，并由 `ffi_api.h` 间接暴露。
5. 错误必须映射为 `mg_error_t` 或稳定 JSON envelope。
6. JSON 字段一旦被前端或外部工具消费，不得无测试地重命名或改变语义。
7. Mission CAD JSON schema 必须版本化；新增字段优先采用向后兼容方式，破坏性语义变化需升级 schema 并记录 ADR。
8. Mission CAD FFI 只接受语义化编辑和编译请求，不得泄漏 widget、鼠标事件、画布坐标或前端语言类型。
9. 命令和查询的 vehicle 目标必须可显式表达；新增接口不得继续扩大对隐式 active vehicle 的依赖。

## 商业授权和侵权边界

1. 本项目是商业项目，新增依赖必须能说明来源和授权。
2. 优先使用 MIT、BSD、Apache-2.0 等商业友好的许可证。
3. GPL、AGPL、SSPL、商业用途不明确、无 license 或来源不明的依赖默认不得进入正式产品。
4. LGPL、MPL、CC 系列素材等需要单独记录使用方式、分发义务和风险后才能采用。
5. 新增第三方依赖前必须记录用途、版本、许可证和替代方案；高风险依赖需写 ADR。

## 仓库卫生

1. 构建目录、dump 输出、临时日志、一次性计划草稿不进入长期源码树。
2. 硬件实验输出默认不保留，除非显式归档并说明用途。
3. `.DS_Store`、本地 IDE 缓存、临时报告不得保留。
4. 历史临时计划、agent 过程记录和已经完成的迁移清单不进入仓库。
5. 已过期命名应删除，不用兼容包装长期拖着。
6. 删除文件前先查引用；删除后必须运行相关验证。
7. 声明提交、diff、分支或工作区状态前必须用 Git 命令实际校验。

## 分支说明

- `main`：完整产品分支，包含前端应用。
- `New-main`：后端与接口分支，只保留 Core、FFI、后端测试和构建工具。前端代码不得重新进入本分支。
