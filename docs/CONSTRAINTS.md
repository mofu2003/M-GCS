# 开发约束

这些约束是长期维护边界。需要突破时，先写 ADR，再改实现。

## 语言和编码

1. 面向维护者、操作员和项目说明的文本默认使用中文。
2. 协议名、API 名、JSON 字段、文件名、目录名和行业通用缩写可以保留英文。
3. 自有文本目标状态是 UTF-8 + LF。
4. CRLF/BOM 归一化必须单独处理，不得混入功能改动。
5. 不为了中文化修改稳定 API、FFI 契约、JSON 字段或协议常量。

## 安全边界

1. 连接状态、命令发送、任务传输、参数写入、校准流程和遥测新鲜度都是安全敏感路径。
2. 持有后端共享状态锁时不得执行阻塞 I/O。
3. 操作员相关错误不能被吞掉；超时、拒绝、能力不可用必须明确暴露。
4. 未经明确确认，不得触发解锁、起飞、任务启动、电机测试、写参数、切模式或危险校准。
5. 真实飞控测试前必须确认飞控未解锁，并说明本次测试会触发哪些命令。
6. `hardware` 和 `manual` 测试不得进入默认自动化门禁。

## 后端约束

1. 优先复用官方 MAVLink 定义和生成产物。
2. 原始 MAVLink 细节必须封装在后端适配器之后。
3. ArduPilot/PX4 差异必须通过 firmware profile 和 capabilities 表达，前端不得猜测固件行为。
4. 参数、任务、校准、命令和连接生命周期变化必须补回归测试。
5. 串口、TCP、UDP、断链处理、显式重连或遥测流请求变化至少运行聚焦测试和默认门禁。
6. 跨平台代码必须显式区分 Windows、Linux、macOS 和 Android。
7. Mission CAD 文档、几何、约束、编译、校验和持久化必须位于后端领域层，不得依赖 `app/`、Flutter、页面名称、地图 SDK 或 UI 控件字段。
8. `MissionPlan` 是面向飞控的派生模型，不能作为可编辑 Mission CAD 文档的唯一事实来源。

## FFI 约束

1. C FFI 不暴露 C++ 类、模板、异常或所有权细节。
2. 所有返回给外部调用方的 `char*` 必须可由 `mg_free_string()` 释放。
3. `mg_event_callback_t` 的 `json` 参数也由回调方负责调用 `mg_free_string()`。
4. 新增 FFI 函数必须放入合适的 `ffi_api_*.h`，并由 `ffi_api.h` 间接暴露。
5. 错误必须映射为 `mg_error_t` 或稳定 JSON envelope。
6. JSON 字段一旦被前端或外部工具消费，不得无测试地重命名或改变语义。
7. Mission CAD JSON schema 必须版本化；新增字段优先采用向后兼容方式，破坏性语义变化需升级 schema 并记录 ADR。
8. Mission CAD FFI 只接受语义化编辑和编译请求，不得泄漏 widget、鼠标事件、画布坐标或前端语言类型。

## 前端约束

1. 目标平台按优先级排序为 Windows、Android、macOS、iOS。
2. Flutter 前端必须保持一套业务 UI 代码；不得为 macOS、Windows、Android 或 iOS 分别长期维护互不一致的页面。
3. Windows 和 macOS 的页面结构、视觉层级、圆角、磨砂、卡片、按钮、表格、状态面板和交互动效必须以同屏一致为验收目标；不得出现 macOS 一套视觉、Windows 另一套视觉的长期分叉。
4. 前端视觉必须最大程度复刻 macOS / iOS 的通用风格气质，包括圆角卡片、磨砂玻璃背景、半透明层级、柔和阴影、清晰工具栏和高质量排版。
5. 复刻的是通用视觉语言和体验质量，不是 Apple 官方资产或受保护界面；不得直接复制 Apple 官方界面、图标、SF Symbols、文案、截图、App Store 资源或任何可能暗示官方关联的素材。
6. 正式业务 UI 必须落到项目自有跨平台设计系统，不能把平台原生控件或第三方 mac/iOS 风格组件直接铺进 feature 页面。
7. 平台差异只允许封装在平台适配层，例如 native library 加载、权限、文件系统、串口/USB/蓝牙、窗口标题栏和移动端安全区。
8. UI 层不得直接导入或调用具体 MgCore FFI 绑定。
9. UI 层不得持有 MAVLink、transport、固件、参数协议或任务传输状态机。
10. 新页面优先接入 `ConnectionController` 或 `ConnectionSessionBackend`。
11. 后端字段映射、遥测组合、连接状态判断集中在应用契约或 MgCore session backend。
12. 操作员关键面板必须信息完整、可扫描；连接、飞控状态、告警和关键设置不得依赖隐蔽交互才能看全。
13. 大面积业务面板、参数表、设置页、日志页默认保持低复杂度和高密度；复杂视觉效果必须先验证性能和可读性。
14. 正式页面优先使用项目内 wrapper，例如 `MgCard`、`MgGlassPanel`、`MgButton`、`MgSegmentedControl`、`MgStatusTile`、`MgDataTable`，第三方组件不得散落在 feature 页面里。
15. 未使用的视觉探索依赖不得保留；第三方 UI 库必须先封装为项目组件，不能成为 feature 页面直接依赖。
16. 磨砂玻璃、透明叠层、阴影和动画在 Windows 与 Android 上必须先做性能验证，再进入高频业务页面。
17. Mission CAD 前端可提供拖拽、吸附和本地交互预览，但不得保留独立的权威几何求解器、航线编译器或 MAVLink 任务项生成器；提交后的结果以 core/FFI 返回值为准。

## 商业授权和侵权边界

1. 本项目是商业项目，新增依赖、图标、字体、图片、地图素材、音效、示例数据和 UI 资产必须能说明来源和授权。
2. 优先使用 MIT、BSD、Apache-2.0 等商业友好的许可证。
3. GPL、AGPL、SSPL、商业用途不明确、无 license 或来源不明的依赖默认不得进入正式产品。
4. LGPL、MPL、CC 系列素材、字体商用授权等需要单独记录使用方式、分发义务和风险后才能采用。
5. 不得使用 Apple 官方 logo、SF Symbols、系统截图、App Store 资源、专有图标或可能暗示官方关联的素材。
6. 可以最大程度借鉴通用的 Apple-inspired / Cupertino-like 视觉语言，但不得逐屏复制某个商业应用、Apple 系统页面或平台专有界面。
7. 新增第三方依赖前必须记录用途、版本、许可证和替代方案；高风险依赖需写 ADR。

## 仓库卫生

1. 构建目录、dump 输出、临时日志、一次性计划草稿不进入长期源码树。
2. 硬件实验输出默认不保留，除非显式归档并说明用途。
3. `.DS_Store`、本地 IDE 缓存、临时报告不得保留。
4. 历史临时计划、agent 过程记录和已经完成的迁移清单不进入仓库。
5. 已过期命名应删除，不用兼容包装长期拖着。
6. 删除文件前先查引用；删除后必须运行相关验证。
7. 声明提交、diff、分支或工作区状态前必须用 Git 命令实际校验。
