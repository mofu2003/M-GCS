M-GCS 全仓结构审阅报告

M-GCS 已形成 C++ 核心、稳定 C ABI 与 Flutter 当前适配器的三层结构。报告聚焦其长期可演进性、交付缺口与 Mission CAD 的正确起点。

核心结论

项目最有价值的资产是后端领域模型和 FFI 契约。保持领域逻辑在 core、语言边界在 FFI、交互在前端，未来更换 UI 不需要重写飞控功能。

系统边界

依赖按单向路径流动。飞控协议、状态机与安全敏感操作不进入 UI。

01 / 交互层 Flutter 与未来 UI 地图、画布、参数页面、状态显示、拖拽与操作确认。
02 / 应用契约 Controller 与 Session Backend 将 UI 语义与 FFI 响应隔离，提供可替换、可测试的能力接口。
03 / 语言边界 bridge/ffi 版本化 C ABI、JSON envelope、错误语义和明确字符串所有权。
04 / 领域核心 C++ mgcore 传输、MAVLink、飞控、参数、任务、校准、遥测与安全状态机。

核心模块

后端已经覆盖的领域范围明显大于当前前端工作流。

  • transport串口、TCP、UDP、内存链路、端口发现与连接生命周期。
  • mavlink + vehicle协议 adapter、命令队列、参数缓存、任务传输、多机与活动飞控选择。
  • firmware + configArduPilot/PX4 profile、模式映射、参数元数据、枚举选项与中英翻译。
  • missionMAVLink 任务、测绘扫描、走廊扫描、导入导出和统计。
  • calibration校准状态机、传感器策略、结果验证与历史记录。
  • telemetry + log遥测缓存、ADSB、飞行日志与 MAVLink 日志能力。

Mission CAD 的边界

参数化航线不属于某个地图页面。可编辑的 `MissionCadDocument`、ENU 坐标、约束、编译、校验和诊断必须属于后端。

  • `MissionPlan` 是飞控目标，不是 CAD 源模型。
  • Flutter、Swift、React、Web、CLI 都只做编辑与渲染。
  • 编译不上传，上传始终是独立且显式的硬件操作。

风险与优先级

优先处理会阻断开发环境、交付闭环或飞控安全验收的问题。

优先级发现影响建议动作
P0MAVLink C 生成头不入库，CI 未执行生成。新机器与 CI 不能保证可构建。固定 `pymavlink` 版本，在 CI 与本地脚本共用 `mavgen` 命令。
P1后端/FFI 能力明显多于 Flutter 工作流。用户可见能力与已有后端资产脱节。按价值接入 Mission CAD、任务传输、诊断和日志，每项先定义应用契约。
P1Windows 最终包与硬件链路尚未完成真实环境验收。桌面跨平台承诺存在交付不确定性。在真实 Windows 主机完成构建、native library 装载和串口只读验证。
P1危险写操作尚未完成真机验收。API 存在不等于可安全发布。为写参数、任务上传、校准、模式切换建立确认、超时、取消和硬件回归矩阵。
P2Mission CAD 仅有设计，没有后端实现。无法验证模型是否满足精确任务规划。先实现 core 文档模型、坐标换算、JSON 往返和离线 fixture 测试。

推荐推进顺序

先恢复可重复验证，再扩展业务能力和 UI。

01 / 基线

构建与 CI 可复现

补 MAVLink 自动生成、执行当前工作区后端与 Flutter 基线测试，并建立可追溯提交点。

02 / 领域

Mission CAD 第一里程碑

建立 `core/mission/cad` 数据模型、ENU/WGS84 换算、`.mgcad.json` 往返和离线 fixtures。

03 / 契约

CAD 预览 C ABI

定义版本化编辑、校验和编译契约；任意 UI 都消费相同的路径、估算和诊断。

04 / 桌面交付

Windows 验收闭环

完成 Windows 构建、native 打包、串口只读连接和桌面端基本回归。

05 / 安全

写操作统一治理

把确认、能力检查、进度、超时、取消和真实硬件验收变成所有危险操作的统一流程。

06 / 多前端

按契约扩展界面

在 CAD 后端稳定后再选择 Flutter、Swift、React 或 Web 的编辑器实现，避免功能重复。

依据当前工作区代码、构建配置、公开 API、测试结构和维护文档整理。

结构审阅不替代当前工作区的重新构建、离线测试或真实飞控验收。
