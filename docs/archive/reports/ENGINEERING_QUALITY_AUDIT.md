#### KD-49：锁序风险（最紧急）

**问题位置**：`mavlink_adapter_internal.h:181-190`

```cpp
void deliver_frame(const uint8_t* data, size_t size) {
    // ❌ 在 send_mtx 内调用外部回调
    LockGuard lock(send_mtx);
    if (!send_cb) return false;
    sent = send_cb(data, size);  // 💣 回调可阻塞，持锁调用
}
```

**问题**：
- 外部 `send_cb` 可能阻塞（TCP 写缓冲满、串口忙）
- 若并发 disconnect → close → 等待 send 完成 → ABBA 死锁
- 已知锁序：`mtx → send_mtx`，反向等待会死锁

**修复建议**：
1. ADR-0005 扩展：定义 `send_mtx` 的边界
2. 改为"锁内复制回调副本、锁外调用"
3. 补"回调重入不死锁"的测试

#### KD-52：所有权模型风险

**问题位置**：`connection_manager.cc:413`

```cpp
[this, mav = mavlink_ptr.get()]  // ❌ 裸指针捕获
```

**问题**：
- 读回调捕获的是裸指针
- 安全完全依赖 `reset()` 的顺序约定（`close()` 先于 `release()`）
- 顺序一改 → use-after-free
- 现有测试不会发现（回调线程与释放线程很少同时运行）

**修复建议**：
1. 改用 `weak_ptr` 或 `shared_ptr` 捕获
2. 在 `reset()` 加断言测试固定顺序

#### KD-51：110 处借用指针阻塞

**问题**：20 个 `.cc` 文件中，110 处调用 `get_active_mavlink()` 后直接调阻塞方法

```cpp
auto mav = get_active_mavlink();  // 借用指针
mav->send_command(...);  // ❌ 可能阻塞，并发 disconnect 则释放
```

**修复建议**：
1. 改为持 `shared_ptr` 租约（已有模板：`shared_active_mavlink()`）
2. 先修 mission/param/log 这三个最易阻塞的
3. 渐进式改造，补回归测试

### 2.4 功能缺陷与断链

#### KD-48：围栏与 ADS-B 无数据源

**现象**：
- `GeofenceManager` 完整实现（18 个方法）
- 但 `points_` 恒空（围栏编辑改走任务协议）
- `mg_geofence_check` 永远返回"在栏外"（实际上没栏）
- ADS-B/距离传感器同样是空数组存根

**决定**：
- ✅ 不删除（有实现、缺接线，属"待开发"而非"死代码"）
- ⏳ 待后续深度开发时接线

#### KD-53：PX4 陀螺校准失败

**现象**：
```cpp
// 只查 ArduPilot 参数名
INS_GYROFFS_X/Y/Z

// PX4 无同名参数 → 回读失败
find_param("INS_GYROFFS_X") → nullptr → ok=false
```

**根因**：参数名硬编码，应由插件下发

#### KD-54：STATUSTEXT 口径不一致

- Gyro/Baro/Accel：严格语义判定（"Success"/"Complete"）
- Radio：宽松子串判定（"RC "、"radio"、"complete"...）
- 同一飞控同一条文案可能在不同校准类型得不同结论
