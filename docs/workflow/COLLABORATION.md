# 仓库协作流程

这是历史协作说明。当前任务以用户指示和根目录 `AGENTS.md` 为准；本文件不再要求
逐项同步旧约束、偏差台账或自动生成的 FFI 目录。

## 任务开始

1. 检查 `git status`，保留已有修改。
2. 按 `AGENTS.md` 确认当前硬约束，只阅读与改动直接相关的代码、测试和资料。
3. 明确改动范围、验收方式和现有局限。简单任务直接执行，复杂任务先列简短计划。

## 多人或多 agent 并行

- 仅在任务需要且得到相应授权时并行；为各协作者分配独立模块或文件。
- 有提交冲突风险时使用独立 worktree，并标明基准提交。
- 共享 FFI、状态模型或构建设置的改动先确认调用方和回归测试，避免各层分别修改成不兼容版本。
- 汇总时由负责当前任务的协作者检查最终 diff、解决冲突，并对汇总后的代码运行门禁。
- 其他协作者的报告是线索，不能代替对最终代码和测试的核对。

## 实现与验证

- 本地阅读、编辑和安全测试按用户授权直接执行，不因文件数量或 agent 名称额外审批。
- 开发期间可使用 `tools/preflight.sh --changed`；提交前运行完整 `tools/preflight.sh`。
- 本地验证包括与改动直接相关的 Flutter analyze/test、C++ offline/simulation 或共享库 smoke。
- 通过本机门禁不代表其他平台已实跑；Windows、Linux、Android 由相应主机或 CI 构建，UI 截图验收另行记录。
- 硬件测试不进入默认自动门禁；需要真实飞控、独占串口和现场确认时单独说明环境与结果。

## 交付

- 文档记录当前行为与真实验证结果，不把待决定事项描述为已实现。
- 不为普通改动新增偏差登记。只有长期架构或发布行为确实需要追踪时才补充记录。
- 最终说明列出修改、验证结果和限制；推送、发布与远端操作按用户明确指示执行。
