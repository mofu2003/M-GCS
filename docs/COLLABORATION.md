# 协作流程

## 默认边界

- 默认只做本地工作，不访问远端；push、tag push、PR 和外部资源操作需用户明确要求。
- 不使用 `git reset --hard`、`git checkout --` 丢弃他人改动。
- 共享飞控串口、Flutter 热重载窗口、`build_check/` 和 git index 都是独占资源。
- 不在持锁路径做阻塞 I/O 或调用外部回调。

## 任务卡

复杂任务开始前记录：

```text
目标：
涉及文件 / 目录：
依赖契约：
不修改范围：
独占资源：
验收命令：
完成标准：
```

## 推荐流程

1. 阅读 `AGENTS.md`、相关领域文档和本地状态。
2. `git status --short --branch`，确认没有未说明的改动。
3. 确定文件所有权；同一文件不由多个并行任务编辑。
4. 先做小范围修改和聚焦测试。
5. 完成后运行 `tools/preflight.sh`。
6. 复核结果时同时确认提交内容与预检内容一致。
7. 本地提交；push 由用户另行授权。

## Worktree

并行工作使用独立 `codex/<short-task-name>` 分支和 worktree。结束后保留提交，
确认不再使用后再归档，不删除用户改动。

## 硬件

飞控串口 `/dev/cu.usbmodem*` 或 COM 端口一次只允许一个进程使用。校准、解锁、
起飞、任务启动、电机测试和写参数前，必须确认机体安全、拆桨并得到明确授权。

## 交接

交接必须包含：当前 branch/commit、完成改动、验证命令、未验证项、未提交改动和下一步。
`.workbuddy/` 只是本机记忆，不是跨 agent 的唯一任务登记处。
